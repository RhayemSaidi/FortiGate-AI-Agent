\section{Introduction}
The administration of enterprise network security architectures is undergoing a period of profound transformation.  With the increasing complexity of the infrastructure, the operational burden on security administrators to continuously manage, update and audit the policies of firewalls has also increased. 

Traditional approaches to network management, from manual intervention through command-line interfaces to static automation scripts, often make it difficult to balance operational agility and strict execution safety.

This chapter has the general framework of graduation project. It begins with the presentation of the host organization, Kleos Tunisia, and operational realities that led to this work. The project is then introduced formally, by presenting the operational context, defining the core problem statement and outlining the engineering objectives. Finally, chapter provides overview of proposed solution and presents methodology and planning used to ensure successful implementation.

\section{Project Presentation}

\subsection{Project Context}
Enterprise networks are growing in scale and complexity, making firewalls an increasingly critical enforcement point for organizational security. However, the operational administration of these devices remains a significant bottleneck. 

Security teams are frequently caught between two suboptimal paradigms: manual administration through command-line interfaces or graphical dashboards, which is slow, cognitively expensive, and highly susceptible to human error; and static automation frameworks, which provide consistency but lack the agility to handle ad-hoc troubleshooting or conversational queries dynamically.

As infrastructure complexity scales, the cognitive load on administrators translates directly into configuration drift, delayed incident response, and service outages. The severity of this issue is quantitatively recognized across the industry; Gartner analysts report that up to 99\% of all firewall breaches are caused by human misconfigurations rather than intrinsic hardware or software flaws~\cite{gartner_firewall}. 

Consequently, there is a pressing operational need to radically simplify how administrators interact with firewall policies, bridging the semantic gap between high-level human intent and low-level configuration syntax.

\subsection{Problem Statement}
Today’s enterprise networks rely heavily on manual interventions and rigid automation scripts for firewall management. This approach dramatically increases the cognitive load of security teams, leading to delayed incident responses, configuration drift, and a high susceptibility to human error~\cite{oppenheimer2003why}. The lack of an intelligent and adaptive interface forces administrators to spend too much time translating high-level security intentions into complex, low-level device configurations~\cite{benson2009network}.

The very essence of the problem that this project addresses is the major operational bottleneck in firewall management, which is typified by error-prone manual processes, lengthy execution times and the inability of traditional automation to respond dynamically to ad-hoc queries.
This creates an urgent operational requirement to greatly simplify the presentation of firewall policies to administrators, in order to bridge the semantic gap between high-level human intent and low-level configuration syntax.

\subsection{Project Objectives}
To solve the problem statement, the main purpose of this thesis is to design, implement and validate a robust hybrid AI orchestration architecture for FortiGate environments. The thesis aims to fill the gap between conversational flexibility and execution safety. The detailed engineering goals are:

\begin{enumerate} 
    \item \textbf{Conversational Assistance:} Provide a natural-language interface capable of accurately interpreting administrative intent to reduce the cognitive load of frequent FortiGate management tasks.
    \item \textbf{Contextual Entity Grounding:} Ensure that extracted intents and network entities are strictly reconciled with the live firewall state before any operational action is considered.
    \item \textbf{Strict Intent Routing:} Establish a clear architectural separation between read-oriented queries (informational) and write-oriented requests (mutations), ensuring only validated actions enter the execution path.
    \item \textbf{Rigid Execution Control:} Confine all policy compliance enforcement, configuration validation, and API execution to a rule-based control plane, effectively isolating the firewall from AI unpredictability.
    \item \textbf{Human-in-the-Loop (HITL) and Operational Recoverability:} Implement a mandatory human confirmation workflow accompanied by pre-change snapshots and rollback capabilities to guarantee operational safety.
\end{enumerate}

\subsection{Proposed Solution Overview}
To achieve these objectives, we propose a hybrid orchestration agent tailored specifically for FortiGate administration. The solution is architected around a fundamental \textbf{Trust Boundary} that physically separates the generative inference capabilities of the LLM from the strict operational requirements of the infrastructure.

Instead of manual API scripting, administrators express their requests in natural language. The system bridges the semantic gap by translating these intents into structured policies, which are mathematically validated against security compliance rules. By mandating a Human-in-the-Loop review before any code reaches the firewall, the architecture provides the conversational agility of an AI assistant while preserving the absolute, state-verified control of traditional enterprise engineering.

\section{Methodology and Planning}

\subsection{Agile Methodology}
The project was executed utilizing an \textbf{Agile engineering methodology}, incorporating iterative sprints to progressively build, integrate, and harden the architecture. This methodology was explicitly chosen over traditional linear models (such as Waterfall or the V-model) because the core challenge of this project---integrating stochastic AI language models with rule-based network infrastructure---requires continuous empirical calibration. 

A rigid methodology cannot accommodate the iterative tuning required to eliminate LLM hallucinations or refine the validation boundaries. The Agile approach facilitated rapid prototyping of the NLU grounding pipeline while simultaneously hardening the strictly-defined REST API control plane.

\subsection{Project Roadmap}
The implementation of this graduation project was arranged in a sequential manner to address the critical dependencies between the rigid execution layers and generative conversational interfaces. A first engineering phase focused on developing and hardening the predictable Python orchestration engine, with all API bindings, state recovery snapshots, and verification pipelines thoroughly tested. The NLU grounding layer was then integrated and deployed alongside the Human-in-the-Loop (HITL) workflow.
